# TailGuardKV 分阶段重构计划

## Summary

目标是把当前“能跑的 measured-replay smoke 流程”重构成“语义闭合的 `profile -> backend -> policy` 链路”，让 baseline smoke 表能够可信回答会话内驻留、跨会话全局驻留、预算命中、`restore/recompute/evict` 行为，并为后续 `tailguard` / `quality_oracle` 扩展提供稳定底座。

默认采用三阶段推进：

1. `P0` 先统一 profile contract，让 profile 层产出完整状态转移证据。
2. `P1` 再重写 measured-replay backend，只消费 profile 证据并显式维护 replay 状态与事件。
3. `P2` 最后把 policy 从 profile-stat ranking 升级为 state-aware action selection，并补齐 smoke / summary / test。

本计划默认不在这一轮引入新的学习模型或复杂 online audit 闭环，只重构数据契约、状态执行和策略接口。

## Implementation Changes

### P0: 统一 Profile Contract 与测量语义

- 定义统一的动作测量契约，拆分“单请求代价”和“状态转移”。
- 强制所有 profile adapter，包括 `full_gpu`、`kivi_*`、`h2o_*`，都写出一致字段：
  - `kv_incremental_mib`
  - `kv_cumulative_mib`
  - `resident_kv_mib_before`
  - `resident_kv_mib_after`
  - `restore_ms`
  - `recompute_ms`
  - `evicted_kv_mib`
  - `budget_hit`
- 将当前“有些 adapter 填 resident 字段、有些为空”的行为改为显式约束：
  - 若某 adapter 暂不支持某字段，必须返回 `0.0` 或带 `extra_transition_missing_reason` 的受控占位，而不是留空。
- 为 profile 层引入 session runtime/snapshot 抽象，使测量按“同 session 连续 turn”产生真实 `before -> after` 状态，而不是只记录单次请求结果。
- 保留现有 `ProfileMeasurement` CSV 兼容列名，但内部重构为两个逻辑子结构：
  - `action_cost`
  - `state_transition`
- 扩展 `smoke_profile_trace`，让其基于真实 transition 输出，而不是只从 measurement 做弱推断。

### P1: 重构 Measured Replay Backend 为状态执行器

- 将 `MeasuredReplayBackend` 从“语义补丁器”改为“证据驱动执行器”：
  - 只消费 profile 层提供的 transition
  - 不再用 profile 缺失数据反推 resident 行为
- 明确三类状态：
  - `local/current request kv`
  - `session resident kv`
  - `global resident kv`
- 为 replay 层建立稳定状态对象：
  - `ReplayState`
  - `SessionState`
  - `CacheEvent`
- 将预算处理拆成显式步骤：
  - `apply measured transition`
  - `check projected global budget`
  - `evict/offload/drop victims`
  - `emit restore/recompute/queue events`
  - `finalize BackendResult`
- `BackendResult` 保持现有 summary 所需字段，但新增或稳定输出事件原因字段，至少覆盖：
  - `event_kind`
  - `event_reason`
  - `victim_session`
  - `budget_resolution`
- 修正 `full_lru` 回放语义：
  - 新 session 不应继承旧 session 的 `resident_kv_before`
  - 但全局池可保持非零 `global_resident_kv_mib`
  - `resident_kv_before` 只表示当前 session 当前动作前可直接复用的驻留
- 将 backend trace 输出升级为一等产物，便于 smoke 表与调试共享同一事件链。

### P2: 将 Policy 升级为 State-Aware Action Selection

- 保留现有 baseline 名称与外部行为，但重构内部接口，让 policy 决策基于 action candidate 而不是 profile 聚合统计。
- 引入统一 action 抽象：
  - `CandidateAction`
  - `ActionDecision`
- 将当前 `StatsPolicy` 的职责拆开：
  - 质量预测/风险上界
  - 成本投影
  - 安全集筛选
  - 最终 STC 选择
- `full_lru` 仍保持 exact baseline，但必须显式读取 `cache_state`，不再是完全无状态返回固定 profile。
- `utility_dynamic` 与 `uncalibrated_dynamic` 继续保留 baseline 语义，但 memory 判断改为使用 replay-visible projected state，而不是仅依赖 calibration 的 `p95_kv_cache_memory_mib`。
- `tailguard` 复用同一 candidate/action executor：
  - QRP/CG 只负责安全性
  - STC 负责预算与最低代价选择
- `StatsPolicy` 若保留，只作为 compatibility shim，不再承担核心决策逻辑。
- summary 层维持现有 CSV 兼容格式，但补强下列解释性字段：
  - `mean_resident_kv_mib`
  - `mean_global_resident_kv_mib`
  - `profile_residence_share`
  - `restore_count/time`
  - `recompute_count/time`
  - `budget_hit_rate`
  - `switch_count`

## Public Interfaces / Types

需要明确调整这些核心接口，避免实现阶段继续隐式漂移：

- `ProfileMeasurement`
  - 保持 CSV 兼容字段
  - 内部语义重定义为“动作测量 + 状态转移测量”
- `BackendResult`
  - 保留现有 summary 所需数值字段
  - 新增稳定事件解释字段到 `extra`
- `CacheState`
  - 从当前偏 backend-internal 的结构升级为 policy/backend 共享状态视图
  - 明确 session/global/state projection API
- `Policy.decide(request, cache_state, device_state) -> Action`
  - 保持签名不变以降低接入成本
  - 但 `Action` 需要能表达 mode/reason/projected memory/risk metadata
- 新增内部类型
  - `ProfileActionCost`
  - `ProfileStateTransition`
  - `ReplayState`
  - `SessionState`
  - `CacheEvent`
  - `CandidateAction`

## Test Plan

必须按阶段补测试，先测 contract，再测 replay，再测 policy。

- P0 contract tests
  - 每个 adapter 产出的 measurement 都包含完整 transition 字段
  - `full_gpu` 不再出现 resident 字段全空
  - 同 session 多 turn 的 `resident_before/after` 单调关系符合预期
- P1 replay tests
  - 新 session 的 `resident_kv_before == 0`
  - 同 session `turn_index > 0` 时可继承已有 resident
  - `global_resident_kv_mib` 可跨 session 保持非零
  - eviction/offload/restore/recompute 在 budget pressure 下事件链正确
  - `full_lru` 不再出现“global resident 非零但 session 语义失真”的回放结果
- P2 policy tests
  - `full_lru`、`static_best`、`static_safe`、`utility_dynamic`、`uncalibrated_dynamic` 在同一 state/action pipeline 下运行
  - `utility_dynamic` 的 memory budget 判断随 `cache_state` 变化而变化
  - `tailguard` 在无 safe lossy action 时稳定 fallback exact
  - summary 中 resident/global resident/restore/recompute 统计与逐条 policy 表一致
- End-to-end smoke
  - `run_experiment.py pilot-smoke-measured --config configs/pilot.yaml`
  - baseline smoke 表包含 5 个 baseline、2 个 budget、4 个 epsilon/delta 组合
  - profile 表、policy 表、summary 表三者的 memory 语义互相一致
  - 至少保留一条小 trace 验证真实 backend smoke 的接口兼容性；若本轮不实现真实 backend 执行，则先补 stubbed contract test 并在后续阶段接入 vLLM / LMCache。

## Assumptions

- 本计划默认优先保证 measured-replay 语义正确，再考虑真实 vLLM / LMCache 接入细节。
- 本计划默认保留现有 CSV 列名和主入口命令，避免打断现有分析脚本。
- `quality` 校准器在本轮不做算法升级，只做接口解耦和状态信息补齐。
- `tailguard` 与 `quality_oracle` 不要求在 P0 / P1 即完成最终论文级行为，但必须能在 P2 接入统一 action/state 管线。
- 若某些 adapter 目前无法直接提供精确 transition，允许在 P0 先通过统一 session runtime 包装补齐，但不得继续留空字段。
