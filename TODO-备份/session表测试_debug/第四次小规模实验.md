# 第四次小规模实验：低预算压力与隐私参数交叉验证

## 目标与口径

本轮不再重跑第二次实验中失败的 **112、128、160、192 MiB**，也不把高预算区域作为主要扫描对象。已有结果已足以说明高预算下不存在显存压力，因此第四次实验集中验证：

1. **15–96 MiB 低预算区间**内预算压力、策略动作和性能曲线是否稳定；
2. **ε、δ 两个参数的 2×2 组合**是否改变预算事件、动作选择或性能表现；
3. 保留 **256 MiB** 这一档失败样本，用于验证失败记录、错误分类和失败聚合链路，不因失败而补跑 112–256 MiB 的其他高预算档位；
4. 以不超过 1 个高预算档位提供“高预算无显存压力”的对照证据，不继续扩大高预算扫描范围。

沿用第三次实验的 **10 请求、8 profile、5 个 baseline、`measured_replay` 和 `baseline_session`** 口径。两个交错 session 的全部 10 条请求必须进入每个成功 cell。实验只验证预算链路、隐私参数敏感性和曲线形态，不据此比较策略优劣，也不声称质量保证；质量指标仍仅作为诊断性证据。

## 实验因素

### 显存预算

实验预算设为：

- 成功预算组：**15、20、25、30、35、50、64、80、96 MiB**；
- 失败验证组：**256 MiB**；
- 不再运行：**112、128、160、192 MiB**；
- 不再向 512 MiB 及以上扩展。

15–96 MiB 用于形成主要分析曲线。256 MiB 只作为已知失败档位进入实验设计和失败链路验收，不得因其失败触发自动补跑、向上扩预算或回填 112–192 MiB。

### ε、δ 参数组合

ε 与 δ 均取 `{0.05, 0.1}`，形成下列四个组合：

- ε=0.05，δ=0.05；
- ε=0.05，δ=0.1；
- ε=0.1，δ=0.05；
- ε=0.1，δ=0.1。

其中 ε=δ=0.1 作为与第三次实验口径衔接的锚点，其余三组用于判断隐私参数变化是否影响策略行为和资源压力。

### Baseline 与种子

沿用第三次实验的 5 个 baseline，并固定使用相同的三个 seed 和各自独立的 profile 划分。所有预算、ε、δ 和 baseline 必须在同一 seed 内复用完全相同的请求顺序、session 交错方式、测量表和 profile 划分，禁止为不同参数组合重新随机划分。

## 实验矩阵

每个 seed 的计划矩阵为：

- 10 个预算档位；
- 4 个 ε/δ 组合；
- 5 个 baseline；
- 每个成功 cell 10 条请求。

即每个 seed 共 **200 个 cell**，三个 seed 共 **600 个 cell**。其中：

- 15–96 MiB：9×4×5×3，共 **540 个主要分析 cell**；
- 256 MiB：1×4×5×3，共 **60 个失败链路 cell**。

如果 256 MiB 的失败是确定性的启动级或环境级失败，可在预检确认错误签名一致后，对每个 ε/δ 组合只保留能够证明失败与参数无关的最小重复证据；被跳过的 cell 必须明确标记为 `skipped_known_failure`，不得伪造为成功结果或普通缺失值。

## 实验前检查

- 保留 session 身份、请求到达顺序和现有测量表；运行类型明确记录为 `baseline_session`。
- 校验配置中的预算、ε、δ、seed、baseline 与请求级记录一致。
- 校验四个 ε/δ 组合均实际传入策略与运行配置，不能只体现在目录名或汇总元数据中。
- 校验三个 seed 使用不同且固定的校准划分，同时同一 seed 内所有实验组复用相同划分。
- 将成功 cell 校验、预算压力校验和已知失败校验分开：高预算无压力不能被判为缺少预算事件，256 MiB 的已知失败也不能污染 15–96 MiB 成功组的整轮状态。
- 在正式运行前执行最小预检，分别覆盖一个低预算成功 cell、一个 ε/δ 非默认组合以及一个 256 MiB 失败 cell。

## 执行步骤

1. **成功组运行**：对 15、20、25、30、35、50、64、80、96 MiB，运行全部四个 ε/δ 组合、五个 baseline 和三个 seed。
2. **失败组运行**：单独运行 256 MiB，保留完整启动日志、退出码、错误阶段和已完成请求数。失败后不重试，不回补 112、128、160、192 MiB，也不向更高预算扩展。
3. **逐请求记录**：保存 seed、预算、ε、δ、baseline、请求 ID、session、turn、动作、policy/backend 命中、过滤、fallback、resident before/after、global resident、卸载或淘汰、恢复、排队、TTFT、KV、质量状态、返回码和错误。
4. **分层聚合**：首先按 `seed × budget × epsilon × delta × baseline` 聚合，再分别对 seed 汇总。禁止先跨 ε/δ 平均后再分析预算曲线。
5. **交互分析**：比较同一预算和 baseline 下四个 ε/δ 组合的预算命中率、动作比例、resident KV、p50/p95 TTFT 与失败率，识别 ε 主效应、δ 主效应及二者组合差异。
6. **高预算结论**：仅用 96 MiB 成功结果以及已有第二次实验高预算证据说明高预算下无显存压力。本轮不通过重复多个高预算档位再次证明该结论。

## 输出与图表

至少生成以下结果：

- 完整 cell 清单和状态表；
- 逐请求原始记录；
- 按 seed、预算、ε、δ、baseline 聚合的统计表；
- 各 ε/δ 组合下的预算命中率曲线；
- resident KV 与 global resident 曲线；
- p50/p95 TTFT 曲线；
- 动作比例、卸载、恢复和排队事件曲线；
- 256 MiB 失败矩阵，包括错误类型、失败阶段、退出码、完成请求数和日志路径；
- ε、δ 主效应及组合差异摘要。

图表必须把四个 ε/δ 组合明确区分，并保留 baseline 和 seed 维度。成功组与 256 MiB 失败组不得在连续折线中直接连接，避免把运行失败误画成性能突变。

## 验收标准

- 每个成功 cell 恰有 **10 条请求记录**，两个 session 均存在，顺序与输入一致。
- 每条记录的实际预算、ε 和 δ 与 cell 配置一致，global resident 不超过实际预算。
- 15–96 MiB 的所有计划 cell 均成功完成；若出现失败，保留证据并将其作为新的异常处理，不自动归入 256 MiB 已知失败。
- 96 MiB 下五个 baseline 不出现预算命中、预算过滤或预算引起的卸载、恢复、排队事件，从而作为本轮唯一高预算无压力对照。
- 低预算区间至少存在一个可由请求级事件解释的压力变化；若四组 ε/δ 均无变化，只报告未观察到敏感性，不扩大预算或临时增加请求寻找差异。
- 256 MiB 的失败必须具有完整错误证据；失败后不重跑，不补跑 112、128、160、192 MiB。
- 汇总指标可由逐请求记录复算，且日志、原始记录、cell 状态和聚合结果语义一致。
- ε/δ 对比必须在相同 seed、预算、baseline、请求顺序和 profile 划分下进行。
- 已知失败、跳过、运行异常和成功四种状态必须分别编码，不能将失败或跳过计为零值。

## 停止与异常规则

- 256 MiB 按预期失败后立即保存证据并结束该 cell，不进行任何自动重试或高预算扩展。
- 112、128、160、192 MiB 无论何种情况都不进入本轮调度清单。
- 若 96 MiB 出现显存压力，只报告其与已有实验结论不一致并停止高预算结论验收，不追加更高预算。
- 若四个 ε/δ 组合未被实际应用、请求数不正确、session 丢失、预算配置不一致或聚合无法回溯原始记录，则停止后续分析并保留现场。
- 单个 baseline 或 seed 的异常不得被跨组平均掩盖，必须单独列出。

## 执行约束

先为 ε/δ 参数传递、实验矩阵生成、已知失败状态、逐请求聚合和高预算无压力校验编写并运行针对性测试，再执行实验预检。

所有正式实验使用 **`nohup` + `setsid` 异步启动**，记录 PID、开始时间、日志和退出码。运行过程中不轮询，待用户通知进程结束后再分析结果。第四次实验写入独立输出目录，不覆盖前三次实验结果或工作树中的已有改动。
