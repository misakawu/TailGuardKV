## 三、已确认的问题与解决状态

### 1. KIVI runtime shape mismatch（已修复并通过 GPU 门禁）

首个 policy cell 中，以下 profile 多次失败：

- `kivi_4bit_residual32`
- `kivi_4bit_residual64`
- `kivi_2bit_residual64`

错误表现为 KIVI 运行时 tensor shape 不匹配，例如 `tensor a (56) vs tensor b (18)`、`tensor a (110) vs tensor b (25)` 和 `tensor a (199) vs tensor b (30)`。

错误证据位于：

`out/full_25session_baseline_9_14/full/seed20260906/logs/eps0p05_delta0p05_mem120p258.log`

该历史失败 CSV 不能作为完整结果。KIVI cache position 对齐和 multi-token residual overflow 已修复，第二次 GPU 最小验证的三轮 KIVI 场景通过。

### 2. Online policy 运行发生 CUDA OOM（根因已修复并通过 GPU 门禁）

`full_lru` 在 `hybrid-session-002-turn-0` 运行时发生 CUDA OOM。日志显示 GPU 0 仅剩约 `5.62 MiB` 可用空间，无法再分配约 `130 MiB`。

根因是 exact action 仍启动独立 full shadow worker，导致同一 audit 同时常驻两份 full 模型。现已直接复用 exact candidate 作为 shadow 结果；GPU 最小验证未复现 OOM。历史失败记录仍不能作为正常性能数据。

### 3. Policy 请求数验收口径不一致（已修复）

当前配置使用 `calibration_fraction=0.5`，并按 session 划分 calibration/evaluation。因此 baseline_session 的 online evaluation 实际只运行 evaluation split，首个 cell 每个 policy 约 `65` 条请求，而不是完整 fixture 的 `125` 条请求。

`scripts/run_session25_fourth_sweeps.py` 已改为从实际 measurement split 推导 expected evaluation request 数和 ID 集合；当前 split 为 calibration `60`、evaluation `65`。

### 4. 当前没有可用 policy 汇总图

`out/full_25session_baseline_9_14/full/seed20260906/policy_tables/session25_policy_eps0p05_delta0p05_mem120p258.csv`
