# H2OCache 与 KV Runtime 整理实施计划

## Summary

实现 `H2OCache`，修复 H2O 在 Transformers 4.43/Qwen2 下的 `DynamicCache` KeyError，并以最小可扩展方式清理 cache/runtime 冗余。完成后补充 TODO：后续添加通用模型适配器。

## Key Decisions

- 重构范围：最小可扩展。只抽共享 cache 工具、实现 H2OCache、清理 H2O/KIVI 直接重复代码。
- 验证强度：单请求真实 H2O profile smoke，加单元测试；不默认重跑完整 `pilot_50`。
- 长度语义：`H2OCache.get_seq_length()` 返回逻辑已见 token 总数；另用 `get_physical_seq_length()`/`h2o_kept_tokens` 表示剪枝后保留 KV 数。
- 原因：profile 层需要真实质量/延迟/显存结果；policy 层消费 profile 统计，不应让 Qwen2 decode position 因 H2O 物理剪枝而倒退。

## Implementation Changes

- 新增 `profiles/cache_common.py`：
  - 提供 Transformers `Cache` fallback。
  - 提供 `reorder_tensor_like()` 和 cache list 初始化工具。
  - `KIVICache` 迁移到该共享工具，行为保持不变。
- 新增 `profiles/h2o_cache.py`：
  - `H2OLayerState(key_states, value_states, hh_score, logical_seq_len)`。
  - `H2OCache` 维护每层剪枝后的物理 KV、heavy-hitter score、逻辑长度。
  - `get_seq_length()` 返回逻辑长度；`get_physical_seq_length()` 返回实际保留长度。
- 修改 `profiles/qwen2_h2o_runtime.py`：
  - H2O attention 保存 `layer_idx`。
  - 不再把 `past_key_value` 当旧式 `(key, value)` tuple。
  - 每个 request 构造并传入 `H2OCache`。
  - prefill/decode 后执行 H2O heavy/recent 剪枝，并更新 tracker 字段。
- 小范围整理 Qwen2 runtime：
  - 保留 `generate_decode()` 和 `install_qwen2_attention()` 作为 Qwen2 专用边界。
  - 不做全模型 adapter 大重构。
  - 添加 TODO：未来抽象通用模型适配器，支持非 Qwen2 attention installer。

## Test Plan

- 新增 `tests/test_h2o_cache.py`：
  - 验证逻辑长度与物理长度分离。
  - 验证 `reorder_cache()` 会重排 KV/score，但保持逻辑长度。
  - 验证 `to_legacy_cache()` 或兼容字段不会触发空层 KeyError。
- 扩展现有 H2O runtime tests：
  - 验证 `_run_h2o_profile()` 会传入 `H2OCache`。
  - 验证 `Qwen2H2OAttention` 拒绝非 H2OCache 的 cache 输入。
  - 验证 tracker 输出 `h2o_prune_events`、`h2o_cache_budget`、`h2o_kept_tokens`。
- 回归测试：
  - `python3 -m pytest tests/test_h2o_cache.py tests/test_kivi_cache.py -v`
  - `python3 -m pytest tests/test_tailguard_core.py -k "h2o or qwen2_runtime" -v`
- 真实 smoke：
  - 用临时 config 只跑 `h2o_heavy10_recent10` 的 1 条或少量请求。
  - 验收：不再出现 `Cache only has 0 layers`；H2O row `ok=True measured=True`，或若请求过短则明确 proof failure 而不是 runtime KeyError。
