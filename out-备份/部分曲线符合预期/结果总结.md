# 部分曲线符合预期：结果总结

这批 `pilot_session_trace` 结果里，比较站得住的信号主要在 `TTFT`、`KV memory` 和 backend 压力事件上，质量曲线本身的信息量反而不大。

先看已经跑出来的主趋势。

`full_lru` 和 `static_safe` 基本一直走 `full_gpu`。它们的显存占用最高，但 `p95 TTFT` 也是最低的一档。`static_best` 则几乎一直压到 `h2o_heavy20_recent20`，所以显存最省，不过延迟明显更高。`utility_dynamic` 和 `uncalibrated_dynamic` 落在中间，没有和两端的曲线完全重合，说明策略切换确实发生了，不是表面上做了 policy sweep，实际动作却一样。

拿 `epsilon=0.05, delta=0.05` 这一组看得最清楚。

- `mem18` 下，`full_lru` 的 `p95 TTFT` 约 `90.96 ms`，`mean_global_resident_kv_mib` 约 `15.38`，`budget_hit_rate` 是 `0.75`。
- 同一预算下，`static_best` 的 `p95 TTFT` 升到约 `141.02 ms`，`mean_global_resident_kv_mib` 降到约 `14.14`，`budget_hit_rate` 只剩 `0.083`。
- `utility_dynamic` 夹在两者之间，`p95 TTFT` 接近 `141.02 ms`，`mean_global_resident_kv_mib` 约 `14.24`，`budget_hit_rate` 约 `0.167`。

这说明两件事是成立的。第一，压缩 profile 确实能把 resident KV 压下去。第二，尾延迟也确实会跟着上来。至少从 session-aware baseline 这条链路看，显存和延迟之间的张力已经出来了。

预算变化本身也符合直觉。随着预算从 `18 -> 26 -> 40 MiB` 放宽，`full_lru` / `static_safe` 的 `mean_global_resident_kv_mib` 明显上升，`budget_hit_rate` 下降。也就是说，backend 的 resident 演化、预算命中和延迟变化是同一条链路上的，不是各说各话。

不过，质量这部分暂时撑不起太强的结论。当前总表里，绝大多数组合的 `mean_quality_loss`、`p95_quality_loss` 和 `violation_rate` 都接近 `0`。图画出来当然会很平，但这种“平”更像是样本和任务强度不够，不像是策略真的把质量和内存同时学明白了。用论文的话说，这批结果可以证明 runtime 行为闭环是通的，但还不足以证明“质量约束下的策略优势”。

还有一个现象需要单独说明。不是所有 policy 在所有预算下都会持续触发 backend 压力事件。`full_lru` 和 `static_safe` 大多还能看到比较稳定的 `restore` 或 `budget_hit`。但像 `static_best`，在 `26/40 MiB` 时已经很接近“主动绕开 backend 压力”的状态，很多点上的 backend event 会明显变少。这个现象本身不奇怪，只是写结果时要说清楚：这里不是 backend 机制突然失效了，而是策略把 resident 压得更低，backend 没什么可处理的了。

如果只问这批图能不能用，我的判断是：

- `summary_policy_p95_ttft.png` 可以用。它能体现 profile 选择带来的 tail latency 差异。
- `summary_policy_kv_memory.png` 也可以用。它和预算变化、策略选择是对得上的。
- `summary_policy_quality_loss.png` 和 `summary_policy_violation_rate.png` 目前更适合作为“结果暂时不明显”的补充图，不适合拿来做主结论。

一句话概括：这批结果已经把 `预算变化 -> resident KV 变化 -> TTFT 变化 -> backend 事件变化` 这条链跑通了，但质量曲线还没真正张开。后面如果要往论文里放，最好把重心放在 session-aware runtime 行为已经成立这件事上，不要过早把它写成质量收益的证据。
